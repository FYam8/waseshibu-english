## G1-002: 時間終了時に客観問題を操作できる

- 重大度P1。次年度入試への準備では、制限時間内に自力で解けた答案の記録が重要。締切後の変更を含む答案をその記録に混ぜない。
- 再現対象: 20a21c9b9ef815f5189569585592bf8a2abde8ce。アプリコードは前段候補と同一。
- 再現CI: 35437417282、390px job 105882333617（1280pxも同じ検査対象）。
- 手順: 隔離contextで本番indexを開く→2024/初見/時間指定10分（検査用設定）→アを選ぶ→検査時計を10分進める→時間超過表示後にイを押す。
- 期待: 客観問題の入力は無効、保存答案はアのまま。記述の自己採点は入力できる。
- 実結果: currentAttempt.overtime=trueになったが選択肢は有効。保存answers['2024:3-1']がア→イへ変更された。CIは保存答案の比較でFAIL。
- 原因: updateTimerはovertimeを保存するだけで、answerRowが設定するdisabled属性を画面に反映しない。reloadでは既存のロックが働く。
- 修正: 初回の期限到達で保存後にrender()しreturn。既存の共通UI/answerRowをそのまま利用し、独自の解答欄を追加しない。
- 対象差分: app.jsのupdateTimerの1分岐。過去の得点・答案の再計算/変更なし。schema、stable ID、正答、配点、習得条件、Engine/UI契約、同期/AI backend変更なし。
- 回帰: live期限前後のUI操作、保存答案一致、客観選択/入力のdisabled、自己採点draft保持、reload後のロック保持。
- 限界: UIの定期タイマー更新時のロックを検査。OS/ブラウザが完全停止している間の実機挙動や、未実施の全イベント競合を保証しない。

## 追加検査の定義

`tests/g1-boundaries.mjs`を既存の隔離実操作runnerから実行。loopback別origin、全外部通信遮断、Jekyll出力とのバイト照合は継続。timezone=UTCを明示。
人工seedと時計設定以外は本番UIのクリック/入力で操作する。内部アプリ関数を呼んで進行状態を作らない。

| 検査群 | 期待する保存・画面の意味 |
|---|---|
| 記述未採点 / 減点理由不足 | 採点確定せず、currentAttemptを保持 |
| 2024正答キー入力・記述1点減点 | 79/80。大小文字と外側空白の許容。これは現行採点回帰であり、公式正答の再照合ではない |
| リスニング0 / 20 / 空欄 | 測定0点と未入力を区別。総合79 / 99 / null。筆記答案と得点は変えない |
| 2023複数選択部分点 / 整序逆順 / 空欄 | 6点問題の正解1つで3点、3点整序逆順0点、3点空欄0点、合計71/80 |
| 同年度やり直し / 採点二重クリック | 次の人工正答答案は80/80、初回71点記録は不変、受験記録は2件のみ |
| 未回答採点の確認を取消 | active答案をそのまま保持、結果を作らない |
| 年度の表示切替 / 別年度で開始 | 表示切替だけでは中断しない。開始時は旧答案を旧attempt IDのinterrupted記録に退避し、新年度を別IDで開始。初回得点も不変 |
| 予定日前 / 翌日の確認 | pendingは予定日前に開始できない。日付変更後に異なる確認問題を2問解答して初めてmastered。これは人工時計での機能検査で、人の定着実証ではない |
| 解答途中に日付変更 | 問題・draftを交換しない。翌日に回答すると新しい日のdrillLogとdailyProgressに1回記録。過去の得点を変えない |
| live制限時間終了 | G1-002の回帰。元の答案を保持し、自己採点欄のみ継続可能 |
